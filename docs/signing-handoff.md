## 公開を依頼された場合の手順

1. 最新main・対象PR・CI・現行配布版を確認。過去の版番号をそのまま採用しない。
2. 対象コードのpackageと設定保存先を確認。既存版より大きいversionCodeと、Manifest・アプリ表示・署名出力名・SHA256SUMS・workflowの一致を確認する。
3. JDK17 / Android SDK35等の既存ビルド手順を使用。既存鍵で署名し、apksignerで署名検証と旧公開APKとの証明書一致を確認。
4. 上書き更新の互換条件と、実端末／エミュレーターでのインストール・設定保持を分けて記録。実行していない試験を合格にしない。
5. 必要なソース・配布資材をPRでmainへ統合。既存のAPKと過去Releaseは保全し、新版をGitHub Releasesへ登録。
6. GitHub Pagesと既存Sitesのダウンロードページを更新。公開設定は維持する。
7. 公開APKを再取得し、生成物・配布メタデータのSHA-256と照合。CI成功、公開完了、実機確認を区別して報告。

2026-10-12に確認したPR #8 head acdadd52f46f93620f7cad15fa6dc22787f59bcf では、scripts/build.shの署名APK出力はcode16だが、末尾sha256sumは旧code15のファイル名を参照していた。次の署名作業時に最新コードを確認し、未修正なら対象をcode16へ揃える。これは当時の確認事項であり、修正済みなら再修正しない。
